# v2 — T0-T4 temporal SSL series

**Status: design / scaffolding.** `data/v2/` and the `v2/` launcher folders exist with READMEs;
no data built or trained yet. See [`VERSIONS.md`](VERSIONS.md) for how v2 sits next to v1.

## Common setup

All five settings are **caption-conditioned video-to-image generation (VC2I)**.

- From each clip, sample four equally spaced frames `F0, F1, F2, F3`; the spacing is `GAP (Δt)`,
  drawn per window from a discrete set (e.g. `{0.25, 0.5, 1.0, 2.0} s`; final set TBD).
- Each sample carries a **video-level caption** that gives semantic grounding but must **not**
  reveal the target frame or the temporal answer.
- Three frames are shown as visual context; one frame is generated as the image target.
- Depending on the setting, `GAP`, `ORDER`, and `MISSING` are either given in the input or
  predicted as text before the image.

## Settings

| Setting | Name | Frame order | GAP | Missing position | Generation target | Text output before `<img>` |
|---|---|---|---|---|---|---|
| **T0** | VC2I-F — forecasting baseline | Ordered `F0 F1 F2` | Given | — | F3 | — |
| **T1** | VC2I-GF — GAP + forecasting | Ordered `F0 F1 F2` | **Predict** | — | F3 | `GAP: <Δt>` |
| **T2** | VC2I-M — explicit masked generation | Ordered, 3 of 4 (F0 always kept) | Given | **Given** | F1 / F2 / F3 | — |
| **T3** | VC2I-OF — ordering + forecasting | `F0 F1 F2` **shuffled**, labeled A/B/C | Given | — (F3 fixed) | F3 | `ORDER: <e.g. B C A>` |
| **T4** | VC2I-Mix | 50% T4-A / 50% T4-B | Mixed | Mixed | Mixed | Mixed |

- **T0:** `[F0, F1, F2] + caption + GAP → F3`.
- **T1:** `[F0, F1, F2] + caption → GAP + F3`. Same frames and target as T0, so T0 vs T1
  isolates the effect of predicting the temporal distance.
- **T2:** pick `k ∈ {1, 2, 3}`, drop `Fk`, show the other three in order, and tell the model
  `Missing: Fk` and the GAP. Generate `Fk`. This covers interpolation (k = 1, 2) and forecasting
  (k = 3); the model does not have to identify which frame is missing.
- **T3:** shuffle `F0, F1, F2` into labels A/B/C, give the GAP, and have the model output
  `ORDER: …` and then generate F3. T0 vs T3 isolates temporal-order prediction.
- **T4-A (50%):** exactly T0.
- **T4-B (50%), full temporal SSL:** pick `k ∈ {1, 2, 3}`, drop `Fk` (F0 always kept), shuffle
  the remaining three into A/B/C, and give **no** order, gap, or missing-position information.
  Output `ORDER: … / GAP: … / MISSING: Fk`, then generate `Fk`.

## Experimental questions

- **T0:** can the model do basic future-frame prediction when order and Δt are given?
- **T1:** does inferring Δt build useful temporal-distance understanding and improve forecasting?
- **T2:** does explicit masked-frame reconstruction (interpolation + forecasting) teach more
  general temporal dynamics?
- **T3:** does recovering the order of shuffled context improve temporal understanding and generation?
- **T4:** does a 1:1 mix of simple forecasting and full `ORDER + GAP + MISSING + generation`
  give stronger world-modeling supervision while keeping a stable forecasting objective?

## Pipeline design

All of T0-T4 derive from **one shared window pool**, so every setting sees the same windows,
the same captions, and the same train/eval split. Only the task formatting differs.

```
raw video + frozen selection manifest (data/v2/sources/<src>/ scripts)
   ──(recipes/temporal_ssl/merge_pools.py: probe → score → plan → extract → finalize)──▶ window pool
       rows: source, clip_id, split, caption, gap, F0..F3 (chronological), motion, meta
window pool ──(recipes/temporal_ssl/derive_settings.py)──▶ T0 / T1 / T2 / T3 / T4 jsonl + trainer meta
```

| Layer | Path |
|---|---|
| Shared library (paths, window rule, static-window scores, frame extraction, QC; planned: prompts + answer grammar) | `data/v2/common/` |
| Per-source download / selection scripts + source docs | `data/v2/sources/<src>/` |
| Recipe (per-source clip loaders, pool builder; planned: derive T0-T4, validation) | `data/v2/recipes/temporal_ssl/` |
| Datasets | `data/v2/datasets/temporal_ssl/{pools/<run>/, settings/<run>/T{0..4}_{train,eval}.jsonl}` |
| Meta | `data/v2/meta/<run>/T{0..4}_{train,eval}_meta.json` |
| Raw video (new sources) | `/scratch/network/ssd/junlin/raw/<src>/` |
| Frames | `/scratch/network/ssd/junlin/v2_frames/<src>/<clip_id>/<frame_idx:05d>.jpg` (outside the repo; ssd2 has too little space) |
| Pool work files (probe/score caches, per-run plans + extract logs) | `/scratch/network/ssd/junlin/v2_frames/_work/temporal_ssl/` |
| Launchers | `training/models/internvl-u/internvl_chat/shell/internvlu/sft/v2/run_t{0..4}_gen_sft.sh` |

| Checkpoints | `/scratch/network/ssd/junlin/models/internvlu-v2-t{0..4}-gen(-merged)` |
| Eval | `eval/suites/v2_temporal_ssl/` |

Training code is expected to need no changes: a text segment followed by `<img>` in one GPT turn
already works (v1's S4). `LM_LOSS_WEIGHT` is 0.0 for T0/T2 and 0.5 for T1/T3/T4.

## Window pool: how to reproduce

The pool is fully determined by the frozen per-source manifests below, the code in
`data/v2/{common,recipes/temporal_ssl}/`, and `SEED = 42`. Each manifest was built by the scripts
in `data/v2/sources/<src>/` (see that README's "Filtering & sampling summary").

**Inputs** (`RAW = /scratch/network/ssd/junlin/raw`):

| Source | Share (`main`) | Candidate clips | Manifest | Caption (verbatim) |
|---|---:|---|---|---|
| PhysicTran38K | 23.5% (14,118) | all 10,000 (not trimmed) | `RAW/physictran38k/selection_10k.jsonl` | metadata `prompt` |
| PhysInOne | 17.6% (10,588) | all 5,000 scenes, 1 static camera each | `RAW/physinone/selection_5k.jsonl` (+ `<case>/rgb/`, `DONE`) | `caption.txt` |
| VBVR | 17.6% (10,588) | `split == "train"` of the manifest; per task a seeded prefix of a fixed shuffle, 1.2 × (quota + eval) / 14 per task | `RAW/vbvr/manifest_all.jsonl` | generator `prompt` |
| BAAI Physics-aware | 17.6% (10,588) | all 5,000 | `RAW/baai_physics/selection_5k.jsonl` | dataset `caption` (Qwen-VL-72B, ships with the data) |
| MiT physics | 11.8% (7,059) | all 5,000 | `RAW/mit_physics/selection_5k.jsonl` | `vlm.caption` from `common/vlm_check.py` (Qwen3-VL-8B, temperature 0), watermark / "N sequential frames" remarks removed by regex; MiT ships only class labels, the file-name stock title is kept in `source_meta` only |
| SSv2 | 11.8% (7,059) | all 10,000 (not trimmed) | `RAW/ssv2/selection_10k.jsonl` | filled-in `label` |

PhyCo-Sim and Panda-70M have manifests and loaders (`clip_sources.py`) but are **not** in `main`
(dropped 2026-09-26). Captions are read from the frozen manifests, so the pool does not depend on
re-running any VLM.

**Parameters:**

| What | Value | Where |
|---|---|---|
| Window rule | Δt ∈ {0.5, 1.0, 2.0} s; N = ⌊T / 3Δt⌋ windows at t = k·3Δt; frame = round(t·fps), last-frame clamp; ≤ 10 windows / clip; clips > 20 s skipped | `common/window_sampler.py` |
| Static filter | drop a window if max(change F0→F1, F0→F2, F0→F3) < 0.001; change = fraction of pixels with \|Δ\| > 25 after 256 px short side, gray, 5×5 Gaussian blur | `common/window_motion.py` |
| Stalled flag | kept; `motion.stalled` = an adjacent pair < 0.001 | `merge_pools.py` finalize |
| Eval | 125 whole clips per source (round-robin over categories), 1 window each (least-used Δt); never in train | `merge_pools.py` plan |
| Train allocation | per-source Δt targets = quota water-filled over available Δt; clips interleaved by category, one window per clip per round; pick Δt furthest below target (tie: scarcest Δt), then least time overlap within the clip | `merge_pools.py` plan |
| Frames | native resolution, downscaled only to fit 1024×1024, JPEG q95; each frame written once | `common/extract_frames.py --max-side 1024` |
| Seed | 42 (per source / run: `Random(f"42:{src}:{run}")`) | `merge_pools.py` |

**Run** (CPU only; `python` = any env with opencv + numpy):

```bash
cd data/v2/recipes/temporal_ssl
python merge_pools.py --stage all --procs 48                 # run "main"
# stages can also be run one by one: --stage probe | score | plan | extract | finalize
```

**Output:** `data/v2/datasets/temporal_ssl/pools/main/<src>_{train,eval}.jsonl` + `summary.json`
(row schema: `data/v2/datasets/temporal_ssl/README.md`). Dry run of `plan` (2026-09-26): 60,000
train windows, Δt 0.5 / 1 / 2 = 26,954 / 26,400 / 6,646 (44.9 / 44.0 / 11.1 %), 11.1% stalled,
static windows dropped 0.2–12.8% per source; 750 eval windows.

**Extra runs:** `--name <run>` with `--quota SRC=N`, `--eval-from main` (same eval clips and
windows) and `--exclude-from main` (no `main` train window reused) build e.g. a larger
single-source set; probe/score caches and frames are shared across runs.

## T0-T4 training data: prompts and derivation

`recipes/temporal_ssl/derive_settings.py --run main` turns the pool into
`datasets/temporal_ssl/settings/main/T{0..4}_{train,eval}.jsonl` (+ `summary.json`) and
`meta/main/T{0..4}_{train,eval}_meta.json` (`task_type: imgen`, `max_dynamic_patch: 3`). ~30 s, no
image IO. Templates and answer grammar live in `data/v2/common/prompts.py` (also used by the eval
parser, `parse_answer`).

- **Every setting uses every pool window once** (60,000 train / 750 eval each), so settings differ
  only in formatting.
- **Prompt layout** (one fixed template per setting): a header sentence defining the frames, then
  `Caption: …`, the three images as `F0: <image>` … (ordered settings, true positions) or
  `A/B/C: <image>` (shuffled settings), `GAP: 0.5|1.0|2.0 s (time between consecutive frames)` when
  given, `MISSING: Fk` in T2, a task sentence, and for text answers an `Answer format:` line.
- **Answers:** one line of compact JSON before `<img>`: T1 `{"gap":1.0}`, T3 `{"order":["B","C","A"]}`,
  T4-B `{"order":[…],"gap":1.0,"missing":"F2"}`; `order` = labels from earliest to latest, `missing` ∈
  F1/F2/F3 (F0 is always shown). T0, T2 and T4-A answer `<img>` only.
- **T4:** the same windows as T0; 50% T4-A (= T0 prompt), 50% T4-B. `T4_eval` holds T4-B for all
  750 eval windows (T4-A eval = `T0_eval`).
- **Balance** (seed 42, per split and source): ORDER permutation (6), missing k (3) and the T4 variant
  (2) are each assigned round-robin over an independent seeded shuffle, so every choice is equally
  frequent and the factors are independent.
- **`cond_image`** = the shown frame nearest in time to the target; tie (missing F1 or F2) → the earlier.
- **Stalled windows are kept**; `answer.order_equiv` lists label pairs that are adjacent in time and
  nearly identical (7.1% of T3 rows), so an eval scorer can accept either order for them.
- Row fields: `id, setting, variant, task_type, source, window_id, clip_id, split, caption, gap_s,
  stalled, image[3], target_image, cond_image, layout, answer, conversations`
  (schema: `data/v2/datasets/temporal_ssl/README.md`).

## Decisions

**Decided (2026-09-24)**

1. **Caption source:** use each source's own caption verbatim (no new captioning stage).
   Exception (2026-09-26): MiT ships only class labels, so it uses the Qwen3-VL caption already
   produced by the VLM QC pass (sampled comparison: it describes the 3 s clip's physical process,
   while the file-name stock titles describe the whole stock video).
2. **`cond_image` (VAE pixel condition) = the observed frame temporally nearest to the target.**
   This does not leak GAP / ORDER / MISSING: the VAE latent goes only into the image-generation
   decoder (`conditional_input` in `modeling_internvlu_unified.py`), while the text answers
   come from the VLM hidden states through the LM head, which never see it.
   *Eval implication:* in T3 / T4-B, "nearest" is defined by the true order / missing
   position. At eval time choose explicitly between oracle `cond_image` (ground truth, which
   measures generation alone) and one picked from the model's own predicted ORDER / MISSING
   (end to end), and report which one was used.

3. **Window pool (2026-09-25, revised 2026-09-26):** Δt ∈ {0.5, 1.0, 2.0} s with the fixed
   per-clip rule (`common/window_sampler.py`, full clips, no trimming). 60K train windows over 6
   sources: PhysicTran38K 23.5 / PhysInOne 17.6 / VBVR 17.6 / BAAI 17.6 / MiT 11.8 / SSv2 11.8 %
   (PhyCo-Sim and Panda-70M dropped 2026-09-26), VBVR train split only; eval = 125 held-out clips
   per source. Δt balanced within each source (dry run: 45 / 44 / 11 %); Δt = 2.0 stays ~11%
   because only clips ≥ 6 s support it, and the user chose to keep {0.5, 1, 2} over a shorter Δt
   set. Windows with no change vs F0 (< 0.1% pixels) are dropped; part-way stalled windows are kept
   and flagged. Frames keep native resolution, capped to fit 1024×1024. Captions are used
   verbatim even when they describe the outcome. Masking / shuffling / answer labels for T0-T4 are
   decided when the training JSON is built. Built by `recipes/temporal_ssl/merge_pools.py`.

4. **T0-T4 prompts (2026-09-26):** structured templates (header / Caption / F- or A-C-labeled
   images / GAP / MISSING / task / answer format) with one-line JSON answers; T4 = same windows as T0,
   50/50 A/B; `cond_image` tie → earlier frame; stalled windows kept with `order_equiv` for eval;
   T4 eval = T4-B only. See "T0-T4 training data" above.

**Open**

5. **Eval protocol** on the held-out pool clips (metrics, oracle vs predicted `cond_image`).
