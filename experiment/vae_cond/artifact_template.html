VAE Condition Ablation

The model sees three frames F0, F1, F2 of a clip and generates the next frame F3. The ViT always gets all three. Only the frames that are also encoded by the VAE and fed to the diffusion decoder change.

Results at a glance

  • No VAE condition fails. Without any VAE latent the decoder does not reproduce the scene. 4 of 5 outputs are a blank field, a text poster, portraits or a contact sheet. Only the fruit has the right object, on the wrong background.
  • One VAE frame (F0) is enough to anchor the scene. 3 of 5 outputs (lizard, cobblestones, fruit) are clean and close to the input frames. The other two (plant, tension strip) are broken: the plant ends up in a bordered panel and the strip scene is mostly empty.
  • All three frames is not better. It matches first on cobblestones and fruit, adds ghosting on the lizard, and breaks the same two scenes in similar ways. The one visible plus is the plant: a few yellow flowers appear, as in the ground truth.
  • No condition produces the physical change. Where the frame is clean, its distance to F2 is about the same as its distance to the ground truth (table), so these are near copies of an earlier frame, not forecasts.

How the prompts are handled

The text is T5's own user turn, identical for the three conditions. The pipeline receives image=[[F0, F1, F2]], so each <image> slot is filled and all three frames go through the ViT.

Here are three consecutive frames sampled from a video clip, in chronological
order and equally spaced in time.

Caption: <PhysicTran38K caption>
F0: <image>
F1: <image>
F2: <image>
GAP: 1.0 s (time between consecutive frames)

Generate the next frame F3, which comes one GAP after F2.

The stock processor builds three classifier-free-guidance rows from it:

The PhysicTran38K caption states the outcome ("the final frame shows a sustained dormant posture…"), so the text alone can describe F3 in all three conditions. This is the same caption caveat as in T5's docs. It probably narrows the gap between conditions, but it does not explain the blank and poster outputs of none.

How the conditions are implemented

The stock pipeline VAE-encodes every earlier image (_prepare_diffusion_inputs → conditional_image). gen.py wraps that method and slices only the VAE-side tensors conditional_image and image_grid_thw_gen_cond to the first 0 / 1 / 3 frames, kept index-aligned. The ViT tensors (pixel_values, encoder_image_token_mask, image_fhw_cond) are never touched. check_inputs.py confirms the counts above on real inputs, and every run logs them in outputs/_meta/.

Two stock-code problems had to be patched at runtime (patches.py; the package is not edited):

  • Processor assert. With 3 frames, the unconditional row (no <image> slots) trips only 1 fake picture in pure text input. That row's image data is discarded anyway, so the assert is skipped for it.
  • Decoder crash for more than one VAE image. _prepare_hidden_inputs_anyres adds a vector of per-image token counts where it needs their sum, so it raised TypeError: only integer tensors of a single element can be converted to an index at 3 images. The patch adds .sum() at the two slice sites. This only affects all; none and first run on the stock path. Training-time code only ever passes one condition image per sample, so the base model has probably not seen several VAE frames at once, which may be why all does not help.

Limits and reproduction

  • 5 datapoints, one noise seed, no repeats. Differences between first and all are within what another seed could change.
  • none, first and all also differ in how many condition tokens the decoder attends to, not only in what information they carry. This run does not separate the two.
